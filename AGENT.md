# AGENT.md — правила проекта «METU IT Club»

Этот файл — единый источник правил для любого ИИ-агента и разработчика, работающего с репозиторием.
Перед любой задачей прочитай его целиком. Если правило мешает задаче — сначала обсуди с владельцем, а не нарушай молча.

---

## 1. О проекте

- **Что делаем:** одностраничный сайт (landing) IT-клуба университета METU — **METU IT Club**.
- **Целевая аудитория:** студенты 1–2 курса. Часто без опыта в IT, ищут сообщество, первые проекты, менторов.
- **Задача сайта:** объяснить, что такое клуб и зачем в него идти, показать направления и мероприятия, довести до заявки на вступление.
- **Тон текстов:** дружелюбный, простой, на «ты», без канцелярита и тяжёлого жаргона. Новичок должен понять всё с первого прочтения.

## 2. Общение и язык

- Отвечай пользователю **на русском языке**.
- Тексты интерфейса — на русском.
- Код, имена файлов, переменных, компонентов, коммиты — на английском.
- Комментарии в коде — на русском, коротко и только там, где без них непонятно «почему».
- Промпты для генерации изображений — на английском (генераторы так работают лучше), пояснения к ним — на русском.

## 5. Архитектура — Feature-Sliced Design (FSD)

Документация: https://feature-sliced.design/

### 5.1 Слои (сверху вниз)

| Слой | Назначение в этом проекте |
| --- | --- |
| `app` | Точка входа: `App.tsx`, глобальные стили и токены темы |
| `pages` | Страницы. Сейчас одна — `home`, она только **собирает** виджеты-секции по порядку |
| `widgets` | Крупные самостоятельные блоки страницы. **Каждая секция лендинга — отдельный виджет** |
| `features` | Действия пользователя: `join-club` (форма заявки) |
| `entities` | Бизнес-сущности, которые нужны **двум и более** слайсам: `direction` (виджет «Направления» + форма заявки) |
| `shared` | Переиспользуемое без бизнес-логики: UI-кит, утилиты, конфиг сайта |

### 5.2 Правило импортов

- Слой может импортировать **только из слоёв ниже себя**: `app → pages → widgets → features → entities → shared`.
- **Запрещено** импортировать из соседних слайсов того же слоя (например, `widgets/hero` → `widgets/about`).
  Нужна общая часть — опусти её ниже (в `entities` или `shared`).
- Импорт слайса — **только через его public API** (`index.ts`):
  - ✅ `import { Hero } from '@/widgets/hero'`
  - ❌ `import { Hero } from '@/widgets/hero/ui/Hero'`
- Внутри слайса — относительные импорты (`./EventCard`, `../model/events`).
- Между слоями — только через алиас `@/`.
- Исключение для `shared`: у него нет слайсов, импортируем по пути сегмента/файла:
  `@/shared/ui/button`, `@/shared/lib/utils`, `@/shared/lib/image-url`, `@/shared/config`.

### 5.3 Когда создавать сущность (entities)

- Сущность выносим в `entities`, **только когда её используют минимум два слайса**.
- Пока данные и карточка нужны одной секции — они живут в сегментах `model/` и `ui/` этого виджета
  (так сейчас устроены события, проекты, команда, отзывы).
- Правило steiger `fsd/insignificant-slice` отключено. На одностраничном лендинге каждый виджет используется ровно один раз,
  а исключение через `files` ломает проверку. Поэтому это правило соблюдаем вручную.

### 5.4 Сегменты внутри слайса

```
<layer>/<slice>/
├── ui/        # React-компоненты (PascalCase.tsx)
├── model/     # типы, данные (тексты, списки), состояние, валидация
├── lib/       # вспомогательные функции слайса
├── api/       # запросы к внешним сервисам
├── config/    # настройки слайса
└── index.ts   # public API — экспортируем только то, что нужно снаружи
```

Создавай только нужные сегменты, пустые папки не плоди.

## 7. Правила для shadcn/ui и `shared/ui`

- Компоненты shadcn добавляй **только через CLI**: `npx shadcn@latest add <component>`.
  `components.json` настроен так, что файлы попадают в `src/shared/ui`, хуки — в `src/shared/lib/hooks`.
- Файлы shadcn — «библиотечный» код. Не переписывай их под одну секцию.
  Нужен особый вид — добавь вариант через `cva` в сам компонент (если он общий) или передай `className` снаружи.
  Уже добавлено: у `Button` размеры `pill` и `pill-lg` (кнопки-пилюли из референса).
- **Все файлы в `shared/ui` именуются в kebab-case** — и от shadcn, и наши. Не переименовывай.
- Не создавай barrel-файл `shared/ui/index.ts` — импортируй каждый компонент по своему пути.
- Наши базовые компоненты в `shared/ui`:

| Файл | Что это |
| --- | --- |
| `container.tsx` | `Container` — единая ширина и отступы секций (`max-w-6xl`) |
| `section-heading.tsx` | `SectionHeading` (надзаголовок + H2 + описание) и `Highlight` (маркерная подсветка) |
| `app-image.tsx` | `AppImage` — картинка с плейсхолдером, если файла ещё нет |
| `clouds.tsx` | `Clouds` — декоративные облака для «небесных» блоков |
| `logo.tsx` | `Logo` — знак и название клуба |
| `people-stack.tsx` | `PeopleStack` — стопка аватарок |
| `telegram-icon.tsx` | `TelegramIcon` — официальная иконка Telegram |

- Компонент, собранный под конкретную бизнес-задачу (карточка события и т.п.), живёт в слое выше, а не в `shared/ui`.

## 8. Дизайн и стили (Tailwind CSS 4)

### 8.1 Визуальный язык (по референсу Studify)

- Небесно-голубые градиенты с мягкими облаками (`from-azure to-azure-soft` + `<Clouds />`).
- Белые карточки с большим скруглением (`rounded-3xl`), тонкой рамкой и мягкой тенью.
- Чёрные кнопки-пилюли (`<Button size="pill" | "pill-lg">`) с цветной тенью `shadow-primary/25`.
- Заголовки секций — `SectionHeading`: маленький серый надзаголовок + H2, часть которого выделена `<Highlight>`.
- Пастельные градиенты у карточек (`bg-pastel-*`), 3D-иллюстрации в стиле Pixar, единый маскот.
- Шрифт Onest, заголовки `font-semibold`, текст — `text-muted-foreground`.

### 8.2 Токены

- Цвета — **только через токены темы**. Хардкод цветов (`bg-[#123456]`, `text-blue-500`, `bg-white`) запрещён.
- shadcn: `background`, `foreground`, `primary`, `secondary`, `muted`, `accent`, `border`, `card` и т.д.
- Фирменные (объявлены в `src/app/styles/index.css`, есть значения для `.dark`):

| Токен | Назначение |
| --- | --- |
| `azure`, `azure-soft` | Небо: фоны hero, заявки, градиенты |
| `highlight` | Маркер в заголовках, акценты шагов |
| `brand` | Логотип, иконки-акценты |
| `pastel-mint`, `pastel-sky`, `pastel-peach`, `pastel-lilac`, `pastel-lemon`, `pastel-rose` | Фоны карточек |
| `tile-blue`, `tile-green`, `tile-orange`, `tile-yellow`, `tile-purple`, `tile-pink`, `tile-ink` | Цветные плашки карточек направлений и цвет иконки на них |
| `sun`, `sun-deep`, `sun-light`, `flame`, `coral`, `paper` | Палитра SVG-иллюстраций (звёзды, огонь, ракета, «белая бумага») |

- Нужен новый цвет — добавь CSS-переменную в `:root` и `.dark`, затем `--color-*` в `@theme inline`.
- Анимации — всегда с `motion-safe:` или `motion-reduce:animate-none`:

| Класс | Где |
| --- | --- |
| `animate-marquee` | Бегущая строка технологий |
| `animate-float` | Покачивание маскота |
| `animate-twinkle` | Мерцание звёзд в SVG |
| `animate-flicker` | Пламя ракеты |
| `animate-bob` | Лёгкое покачивание SVG-объекта |
| `animate-puff` | Клубы дыма |

### 8.4 SVG-иллюстрации

Мелкие декоративные иллюстрации (стикеры, значки-картинки) не эмодзи и не растровые картинки,
а **анимированные inline SVG-компоненты** (пример: `widgets/about/ui/SparklesIllustration.tsx`, `RocketIllustration.tsx`).

- Компонент лежит в `ui/` того слайса, где используется. Нужен двум слайсам — переносим в `shared/ui`.
- Цвета — только токены: классы `fill-*` / `stroke-*` или `var(--token)` в `stopColor` градиентов. Никаких hex.
- `id` градиентов — через `useId()`, чтобы не было конфликтов при нескольких копиях.
- Анимации — keyframes в `src/app/styles/index.css` + токен `--animate-*`. На SVG-элементе обязательно
  `transform-fill` и `origin-*`, иначе трансформация считается от угла холста.
- `transform` в атрибуте и CSS-анимацию transform не ставим на один элемент: позиция — у обёртки `<g>`, анимация — у ребёнка.
- Задержку анимации задаём через `style={{ animationDelay }}`: класс `[animation-delay:…]` перебивается шорткатом из `motion-safe:animate-*`.
- SVG декоративный: `aria-hidden`, `focusable="false"`.

### 8.3 Общие правила

- Только utility-классы Tailwind. Отдельные `.css`-файлы для компонентов не создаём.
- Условные и объединяемые классы — через `cn(...)`.
- **Mobile-first**: базовые классы для телефона, затем `sm:`, `md:`, `lg:`. Проверяй ширину 375px — без горизонтального скролла.
- Ширина контента — только через `<Container>`.
- Вертикальный ритм секций: `py-20 md:py-28`.

## 9. Код-стайл

- Только функциональные компоненты и хуки.
- **Именованные экспорты.** `export default` — только там, где этого требует инструмент (конфиги).
- Компоненты и их файлы вне `shared/ui` — `PascalCase` (`EventCard.tsx`). Хуки — `useCamelCase`. Слайсы и папки — `kebab-case`.
- Тип пропсов — `type XxxProps = { ... }` рядом с компонентом.
- Без `any`. Без `// @ts-ignore`. Без неиспользуемого кода и закомментированных кусков.
- Типы импортируй через `import type` (включён `verbatimModuleSyntax`).
- Нечистые вызовы (`new Date()`, `Math.random()`) — не в рендере, а на уровне модуля или в эффектах.
- Форматирование: одинарные кавычки, без `;`, ширина строки 100, висячие запятые.

## 10. Изображения

- **Агент не генерирует изображения сам.** Для каждой новой картинки он:
  1. придумывает имя файла (`kebab-case.webp`);
  2. добавляет промпт в [`docs/image-prompts.md`](docs/image-prompts.md) — в общем стиле, с форматом и требованием к фону;
  3. отдаёт промпт владельцу в ответе.
- Все картинки лежат в `public/images/`, путь собирается через `imageUrl('file.webp')` из `@/shared/lib/image-url`.
- Выводим только через `<AppImage>`: пока файла нет, он показывает плейсхолдер с именем файла.
  Аватарки — через `Avatar` / `PeopleStack`, у них фолбэк — первая буква имени.
- Формат — WebP. Персонажи и иконки, которые лежат поверх фона, — с прозрачным фоном.
- Стиль всех иллюстраций единый: 3D в духе Pixar, пастель, голубые акценты, без текста и логотипов.
- Маскот один на весь сайт; его описание в промптах не меняем.
- Когда владелец присылает готовые картинки, агент сам:
  1. сопоставляет их с файлами из таблицы в `docs/image-prompts.md` и отмечает статус «✅ готово»;
  2. убирает фон, если в таблице указан прозрачный: `swift scripts/remove-bg.swift <in> <out.png> [padding] [x,y,w,h ...]`
     (Apple Vision; области `x,y,w,h` — для мелких объектов, которые Vision теряет);
  3. сжимает в WebP через `cwebp` (фото и сцены `-q 78–80`, прозрачные `-q 82 -alpha_q 90`),
     карточки уменьшает до ~1000px по ширине, большие фоны оставляет ~2000px;
  4. проверяет результат в браузере на 1280px и 375px.
- Картинки, присланные прямо в чат, на диск не попадают. Если файла нет — попроси прислать файлом
  или положить в `public/images/`.

### 10.1 Фото из открытых источников

Сейчас с Unsplash взяты: аватарки, портреты команды, фото проектов и главного события в афише.

- Источник — только **Unsplash** с меткой «Free to use under the Unsplash License» на странице фото.
  Фото **Unsplash+** — платные, не берём.
- Скачиваем с CDN сразу в WebP нужного размера: `https://images.unsplash.com/<photo-id>?<параметры>`.
  Аватарки — `w=256&h=256&fit=crop&crop=faces`, портреты — `w=640&h=640&fit=crop&crop=faces`,
  карточки — `w=1200&h=750&fit=crop`, большие — `w=1400`; всегда `fm=webp&q=78–80`.
- Каждое фото записываем в [`docs/image-credits.md`](docs/image-credits.md): файл, автор, ссылка на оригинал, `photo-id`.
- Один и тот же человек не должен появляться под разными именами: фото из одной фотосессии
  (соседние `photo-id` одного автора) для разных персонажей не берём.
- Стоковые лица — **только заглушки для разработки**. Нельзя выдавать посторонних людей за участников и команду клуба
  и ставить их рядом с придуманными отзывами на живом сайте. Перед запуском — реальные участники с их согласия.

### 10.2 Иконки

- Иконки интерфейса и карточек — только `lucide-react`. Карточки «Направлений» — без картинок:
  линейная иконка lucide (`strokeWidth={1.5}`, цвет `text-tile-ink`) на цветной плашке `bg-tile-*`.
- Telegram — только официальная иконка: `<TelegramIcon />` из `@/shared/ui/telegram-icon` (файл `telegram.webp`).
  Остальные соцсети — иконки lucide в чёрных кругах (`bg-primary text-primary-foreground`), чтобы ряд выглядел единым.

## 11. Данные и контент

- Тексты и списки секций **не хардкодим в JSX**. Данные — в `model/` слайса, общие данные сайта — в `shared/config`.
- Заглушки помечай комментарием `// TODO: контент`, чтобы их было легко найти: `grep -rn "TODO: контент" src`.

## 12. Доступность и SEO

- Один `<h1>` на странице (в `hero`). У каждой секции — свой `<h2>` (если визуально его нет — `sr-only`).
- Каждая секция — `<section id="...">`; `id` совпадает с именем виджета.
- Семантические теги: `header`, `nav`, `main`, `section`, `footer`, списки — `ul`/`ol`.
- У изображений — осмысленный `alt` (декоративные — `alt=""`).
- Иконки-кнопки — с `aria-label`. Всё интерактивное доступно с клавиатуры, фокус виден.
- Поля формы — с `Label`, ошибки связаны через `aria-describedby`, `aria-invalid`.
- Контраст текста не ниже WCAG AA.

## 13. Производительность

- Картинки — `loading="lazy"` везде, кроме первого экрана (`fetchPriority="high"` у hero).
- Не тянуть тяжёлые библиотеки ради одной анимации или иконки.
- Иконки — только `lucide-react`, импорт по одной. Исключение — Telegram (см. раздел 10.2).
